## このページの目的

Claude にツールやサイトを作ってもらうと、変更は **ブランチ**（作業用コピー）に届きます。
それを **自分でプルリクエストにして、自分でマージ** できるようになるのが目標です。

まずは練習として、`about.md` の文章を1か所だけ直す変更で、最初から最後まで一人でやってみます。

## 最初に覚える 4つの言葉

| 言葉 | 意味 |
|---|---|
| リポジトリ | ファイルを入れておく箱（このブログなら `BOM`） |
| ブランチ | 箱の中の作業用コピー。本番は `main` |
| コミット | 変更を保存すること。メモ（コミットメッセージ）を付ける |
| マージ | ブランチの変更を `main` に合流させること |

**プルリクエスト** は、「このブランチの変更を main に入れてください」という提案書です。
main を直接いじらずに「コピーで変更 → 中身を確認 → 合流」の順で進めるので、失敗しても本番が壊れにくくなります。

## 練習の手順（5ステップ）

### 1. ファイルを編集する

1. GitHub でリポジトリを開き、`about.md` をクリック
2. 右上の **✏（鉛筆）** ボタンを押す
3. 文章を1か所だけ直す（例：「まとめています」→「少しずつまとめています」）
4. 右上の緑の **Commit changes...** を押す

### 2. 新しいブランチに保存する（いちばん大事）

「Commit changes」の画面で、

1. Commit message（変更のメモ）はそのままでも、自分で書いてもOK
2. **Create a new branch for this commit and start a pull request** を選ぶ
   - 上の「Commit directly to the main branch」を選ぶと、プルリクエストを作らずに直接本番へ入ってしまいます
3. ブランチ名（`patch-1` など）はそのままでOK
4. 緑の **Propose changes** を押す

### 3. プルリクエストを作る

「Open a pull request」の画面になります。

1. 上のほうが **base: main ← compare: patch-1** になっているか確認
   （＝ patch-1 の変更を main に入れる、という意味）
2. タイトルを確認（説明は空でもOK）
3. 緑の **Create pull request** を押す

### 4. 中身を確認して、マージする

1. **Files changed** タブを開き、変更内容を見る
   - 赤い行（−）＝消える行、緑の行（＋）＝増える行
2. **Conversation** タブに戻り、下のほうに「✔ No conflicts with base branch」が出ているか確認
3. 緑の **Merge pull request** を押す
4. もう一度出てくる **Confirm merge** を押す
5. 紫の **Merged** になれば合流完了

### 5. 後片付けと、サイトへの反映

1. 「Pull request successfully merged and closed」の横の **Delete branch** を押す
   （使い終わったコピーを片付けるだけ。変更は main に入っているので消えません）
2. 上の **Actions** タブで「pages build and deployment」が ✅ になるのを待つ（1〜2分）
3. ブログを再読み込みして、文章が変わっていれば成功！

## 本番：Claude が作った変更をマージする

Claude は変更を `claude/○○○` のような名前のブランチにプッシュしてきます。

1. リポジトリのトップを開くと、黄色い帯に「**claude/○○○ had recent pushes**」と出る
2. 緑の **Compare & pull request** を押す
3. あとは練習と同じ：手順3（作る）→ 手順4（確認してマージ）→ 手順5（削除・反映）

**黄色い帯が出ないとき**：**Pull requests** タブ → **New pull request** → 「compare」を `claude/○○○` に変える → **Create pull request**

> 💡 Claude に頼むときは「プルリクエストは自分で作るので、ブランチにプッシュするところまでお願いします」と伝えると、練習の機会になります。

## 困ったときは

| 画面に出たもの | 意味と対処 |
|---|---|
| ⚠ This branch has conflicts | 同じ場所を別々に変更していて、自動で合流できない状態。Claude に「コンフリクトを直して」と頼む |
| ❌ チェックが赤い | 自動テストや処理が失敗している。画面を Claude に見せる |
| マージを取り消したい | Merged になったプルリクエストの画面の **Revert** ボタンで「元に戻す」プルリクエストが作れる |
| どれを押すか迷った | 押す前に止まってOK。スクリーンショットを Claude に見せて聞く |

## まとめ：チェックリスト

- [ ] 変更は **ブランチ** で（main に直接は入れない）
- [ ] **base: main ← compare: ブランチ** を確認
- [ ] **Files changed** で中身を見る
- [ ] **Merge pull request → Confirm merge**
- [ ] 紫の **Merged** を確認 → **Delete branch**
- [ ] Actions の ✅ を見てからサイトを確認

> ⚠ GitHub の画面は、アップデートでボタンの名前や位置が少し変わることがあります。見つからないときは、似た名前のボタンを探すか、画面を Claude に見せてください。
